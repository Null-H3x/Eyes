# Eyes — Tooling Reference

*A directory-by-directory guide to every tool in `Null-H3x/Eyes`: what each one is, and what it's used to test. Descriptions are drawn from the tools' own docstrings and READMEs (as of commit `6fe7bb6`, 2026-07-20).*

**The target.** Noita's nine in-game "eye messages": 1,036 symbols over an 83-rune alphabet, cipher family / PRNG / key all unknown. The corpus is established to be *in depth* — the messages share a position-indexed keystream — and the leading model is the linear class:

```
c_m[t] = C[(σ·p_m[t] + base_m + drift·t) mod N]      N = 83 (prime)
σ ∈ {+1, −1},  drift ∈ {+1, 0, −1},  C a mixed alphabet,  q = C⁻¹
```

**The shape of the toolkit.** Work splits into two efforts plus a shared foundation:

- **Effort A — verify (EyeWitness):** produce true, reproducible structural results whether or not the puzzle is ever solved.
- **Effort B — decrypt (EyeCrack, EyeStat, EyeSieve, eyesolver, the crib stack):** the bet — actually recover plaintext, gated by calibrated statistics so nothing gets called a "hit" without surviving multiple-testing correction.
- **Foundation (noita_eye_core):** one tested implementation of the shared math, guarded by an aggregate selftest ("the math gate"). Nearly every tool below ships its own paranoia selftest that plants ground truth, attacks it, and asserts recovery — a clean run is evidence for the model, not just the code.

## 3. `noita_eye_core/` — the shared foundation

**What it is.** The single tested home for the math shared across all tools (IoC, modular ciphers, corpus loading, language models) *plus* the depth / crib-drag keystream-recovery layer — the N-way depth attack that exploits the shared keystream. Everything is validated by `selftest.py`, the aggregate math gate (hundreds of ground-truth checks); the audits found the older tools re-implementing the same math three times, and this package fixes that.

**Key algebra it encodes:** under any linear combiner, `c_i[t] − c_j[t] = plain_sign·(p_i[t] − p_j[t]) mod N` — the key cancels, so plaintext *difference* structure is recoverable with no key (multi-ciphertext Vigenère).

## 4. `eyewitness/` — Effort A: the verifiable fingerprint

**What it is.** Answers **one falsifiable question** and signs the answer: are the 9 messages organised as *pairs + a special E5* (Theory 1) or as *triplets* (Theory 2)? It never decrypts — it emits a deterministic, null-calibrated `fingerprint.json` plus the crib contract EyeCrack consumes, and ships `verify_fingerprint.py` (numpy-only, stack-independent) so a skeptic can reproduce the headline numbers from raw runes.

**What it computes:** depth premise (shared keystream ~57σ above shuffle null) → partition model selection by profile log-likelihood → data-driven cliques with no theory imposed → robustness after stripping the shared opening → significant identical spans (the cribs) → power analysis.

## 5. `eyecrack/` — Effort B: depth-fed decryption attacks

**What it is.** The *bet*: actually recover plaintext using the depth structure EyeWitness certifies. Every candidate routes through the **calibrated joint oracle** — a "hit" must make all in-depth messages decrypt to language-like text *simultaneously* and survive Bonferroni correction for the entire search (the trust gate the community's unconstrained seed scans lack; the true keystream's z grows like √total_symbols).

Three prongs, cheap → expensive: `crib` (exact crib-drag, works now), `viterbi` (needs a real LM), `seedscan` (calibrated PRNG brute force — the GPU target).

## 6. `eyeforward/` — the pin-densification pipeline

**What it is.** Forward-moving modules built on `noita_eye_core`, targeting the per-message-progressive model where recovering `q = C⁻¹` collapses the corpus to a shared monoalphabetic cryptogram. Every module ships a paranoia `selftest()` that plants ground truth and **fails loudly** when an attack only pretends to work — the audits prove attacks *fail* on autokey/Alberti data rather than emitting garbage. (Aggregate: `selftest.py`, ~75 checks across 7 modules.)

Pipeline: `iso_relax` (anchor graph) —pins→ `support_min` (recover q) —q→ `order_anneal` (shared mono-sub solve) → plaintext.

| Module | What it tests |
|---|---|
| `iso_relax.py` | Densify the anchor graph with calibrated/approximate isomorphs. |
| `support_min.py` | Language-free attack on the plaintext-value permutation q via support minimisation. |
| `order_anneal.py` / `order_gpu.py` | The shared monoalphabetic solve on the reduction; CuPy-batched acceleration (NumPy fallback). |
| `ordering_bridge.py` | Same-day verdicts for alphabet-ordering hypotheses. |
| `alphabet_sweep.py` | Exhaustively disposition *structured* alphabet families. |
| `model_power.py` | How much does the progressive-consistency test actually **prove**? (Key caveat it makes precise: isomorph evidence pins the linear *class* `{pmp, pure, beaufort}`, not pmp uniquely — read steps must try both +p and −p.) |
| `pyry_gate.py` | Dev-conditions oracle + chain-family battery (testing the community's Alberti-autokey reading). |
| `plantlab.py` / `selftest.py` | Shared ground-truth plant generators; the aggregate paranoia audit. |

For each seed: decrypt → chi² shape filter on GPU → dictionary-score survivors on CPU → per-shard results + merged deliverable + auto HTML report.

## 8. `eyesieve/` — combinatorial structural sieve

**What it is.** The sibling line to EyeStat: instead of sweeping seeds, it sweeps a constrained hypothesis space of **(partition × source-merge × key-derivation × cipher)** configurations through a cascading sieve, surfacing the small set worth full statistical scoring. Tests the community's structural theories directly: **Theory 1** — `merge(E_i, W_i)` decrypted with E5 as the key; **Theory 2** — the key is a *transformation* of E5 (self / cross / constant variants). Shares the corpus and EyeStat's scoring backend.

## 9. `Eyesolver/` — the classical dual-model solver

**What it is.** `eyesolver.py` is the purpose-built equivalent of running AZDecrypt / stblake-polyalphabetic against the corpus — those tools are hardcoded for 26-letter alphabets and can't ingest N=83-with-scattered-embedding, so this reimplements the same algorithm class (shotgun hill-climb + simulated annealing + real 3-gram objective + crib anchoring) for the exact structure, seeded by the 16 gauge-invariant pins. It covers **both** competing models with one engine: `static` (the repo's Quagmire-IV-with-progressive-key reading, vectorized) and `autokey` (the community's plaintext-autokey Alberti reading, sequential).

**What it established (the finding, not just the tool):** the selftest proves both engines *sound* — they recover planted plaintext when seeded near the solution — but quantifies the wall: **from the 16 pins we actually have, neither model converges** (static stays at the ~8% random floor; search only becomes navigable at ~60 of 83 correct q-values; cribs help marginally for static and *hurt* autokey via state propagation). Practical consequence: more compute won't solve it from 16 pins — the landscape, not the speed, is the block. It becomes a solver the moment pins cross ~40–60.

`eye_crib_solver.html` (the Eye Crib Tester) lives here too — see §2.

## 11. Specialized probes & gates

| Tool | What it is | What it tests |
|---|---|---|
| `isoscan/isoscan.py` | Isomorph-constrained language scanner | Takes the 13 community-catalogued isomorph patterns and scans English / Finnish / Livvi-Karelian corpora for windows consistent with each pattern **per cipher-model hypothesis** — because under autokey/progressive ciphers, ciphertext isomorphs do *not* transfer to plaintext directly (per Pyry's Alberti demo). Each mode builds the correct derived stream (`direct`, `delta:D`, `sigma:D`) and matches against that. Outputs: `isoscan_hits.tsv`, `isoscan_report.txt`. |
| `dedrift/dedrift_probe.py` | Plaintext **type** fingerprinter | Fingerprints the plaintext's statistical type through the de-drift channel *without* recovering the full alphabet: `d[t] = q[c_m[t]] − drift·t` is a monoalphabetic image of the plaintext, readable at every position carrying one of the 16 gauge-invariant pins. Collision statistics (IoC, triple-rate) are invariant to every gauge nuisance (σ, base, rotation), so the channel measures whether the plaintext behaves like language, structured non-language, or noise. |
| `deck lab/deck_lab.py` | Cipher-**family** lab (rebuilt after review) | Tests which cipher *classes* are compatible with the corpus's observables, fixing three flaws of its own first cut (documented in the docstring): re-sync separates position- vs content-indexed keystreams, *not* linear vs deck; isomorph/doubles behavior must be measured on structured (lore-sampled) plaintext, not random; and it runs the real algorithms, not proxies. |
| `order gate/order_gate.py` | Priority-1 **two-crib order-overlap gate** | The alphabet links but doesn't order (~16 sound pins; `support_min` needs ~22, 100% by ~40). Two overlapping crib targets exist — T1 the 4× refrain (L=22) and T3 the Triplet-3 dof-1 passage (L=30) — sharing **31 distinct cipher symbols** with a union covering **69/83 (83.1%)**. A correct (T1-phrase, T3-phrase) pair therefore faces 31 hard equality checks; passing welds a 69-symbol map, past `support_min`'s floor. This is the highest-leverage single test in the repo. |
| `injectlab/eyegate2.py` | **Gate 2** — order-aware refrain admissibility | The certified refrain template pins the 22-glyph refrain's relative plaintext to dof=2 (every pair forced to a numeric difference mod 83). Gate 2 asks, for a candidate *phrase* × candidate *alphabet order*: does any embedding of that cyclic order into ℤ₈₃ satisfy every forced difference? Strict cascade A (same-groups) → B (full pattern, 207 forced-different pairs) → C (numeric union-find over ±σ) → D (embeddability via Bellman–Ford difference constraints). |
| `tool1/tool1.py` | Closure residual + acquisition ranking | On the contamination-filtered isomorph set from `chain_extract`: computes the honest residual budget (what's genuinely still unknown) and an information-gain ranking of *what to acquire next*. Rails: per-message-progressive is treated as a conditional candidate; never pins a value or claims a cross-triplet magnitude. Result snapshot in `tool1_result.json`. (Note: carries a hardcoded `sys.path` from its authoring session — adjust before running elsewhere.) |

## 13. `report/` — the evidence ledger

**What it is.** Builds `report.html`, the self-contained "Grimoire" dashboard of every hypothesis's standing. Enforced design rules: the dashboard **never computes its own math** — each card renders results from a selftested `noita_eye_core` module and carries a validation badge tying it to that module's ground-truth selftest; output is fully self-contained (inline CSS + inline SVG, no CDN) so a skeptic can view-source every number; verified *exclusions* are first-class results, and an ARTIFACT tier loudly labels findings that were significant only before a confound control.

`build.py` runs the math gate → computes every hypothesis (`hypotheses.py` registry; adding a dart = one function) → `core.py` renders → appends to `ledger.json`. Generated markdown/JSON snapshots of individual tool runs (`*_report.md`, `eyescoreboard.*`, `keyspace_ledger.*`) live alongside.

## Quick orientation for a new contributor

1. `python3 full-installer.py` — venv + smoke test of everything.
2. `python3 run.py` — open the workbench.
3. `cd noita_eye_core && python3 selftest.py` — the math gate; trust nothing until it's green.
4. Read `WAY_FORWARD_next.md` for what's proven vs leaned, then `eyewitness/README.md` (what's certified) and `eyecrack/README.md` (how attacks are gated).
5. The two highest-leverage open tests: `order gate/order_gate.py` (the 31-check two-crib weld) and lexicon-quality improvements feeding `eyecrib/eyecrib_sweep.py`.
