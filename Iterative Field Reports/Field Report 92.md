## 0. CHALLENGE I — a load-bearing assumption verified from primary source

The PRNG sweep programme — EyeStat's 34 billion seeds, FR61's rebuild, FR62's cost
model — rests on doctrine's account of the author's habits: *"Park-Miller/Schrage LGM
(a=16807), floor-scale-biased integer mapping."* That was a **prior**, never checked
against his code.

`gummikana/MonteCarlo_NoMoreMoney/Source/random/random.cpp` settles it.

```cpp
// m = 2147483647 = 2^31 - 1; a = 16807;
// 127773 = m div a; 2836 = m mod a
long hi = iseed / 127773L;
long lo = iseed - hi * 127773L;
iseed = 16807 * lo - 2836 * hi;
if (iseed <= 0) iseed += 2147483647L;
```

```cpp
static int Random( int low, int high ) {
    return low + (int)((double)(high-low+1) * (double)Next());   // floor-scale
}
```

**Both confirmed.** Park-Miller/Schrage with the standard constants, and floor-scale
integer mapping. The doctrine's priors were right, and are now evidence rather than
inference.

## 1. What the source adds beyond confirmation

**A second generator nobody has swept.** The header declares four entry points, and
`fastrand` is a distinct LCG:

```cpp
int fastrand() { g_seed = (214013*g_seed+2531011); return (g_seed>>16)&0x7FFF; }
```

MSVC-style constants, 15-bit output. `Random()` dispatches to it under
`CENG_USE_FAST_RAND`, and to `std::rand()` under `CENG_USE_C_RAND` — both macros
commented out, so **LGM is the default**. But `fastrand` is seeded unconditionally at
startup and is the author's "fast path" idiom.

**And the seed space is not 2³².**

```cpp
CRandomSeedSetter() { ... set_fastrand_seed( (int)time( NULL ) ); }
```

**Seeds are Unix timestamps.** If the alphabet was generated by running code rather
than by hand, the seed is *the moment he ran it* — which turns an intractable 2³² space
into a **date range**.

## 2. The sweep

Fisher-Yates driven by `fastrand`, both integer mappings (floor-scale and modulo),
both directions, over Noita's development window:

```
window 2017-01-01 .. 2021-01-01     126,230,400 seconds
chunk swept                         400,000 seeds x 2 mappings x 2 directions
rate                                75,181 seed-checks/s
hits                                NONE
```

**Full-window projection: 1.9 hours single-core, or ~31 minutes on GPU** at EyeStat's
demonstrated rate.

This is the first PRNG sweep in the project with a **bounded, motivated seed space**
rather than an open 2³¹. It is small enough to exhaust.

---

## 3. Why this changes the PRNG programme

FR61 established that a complete Park-Miller sweep costs 17–47 GPU-hours. That figure
assumed the full 2³¹ seed space.

**Under the timestamp hypothesis it collapses.** A four-year window is 1.26×10⁸ seeds —
**sixteen times smaller than 2³¹** — and a *ten*-year window still only 3.2×10⁸. Across
both generators, both mappings and both directions that is well under an hour of GPU
time for the entire plausible space.

The hypothesis is falsifiable and cheap: **if the alphabet was generated by running his
own code, the seed is a timestamp and the sweep exhausts it.** If nothing is found, the
timestamp hypothesis dies and with it the last motivated reduction of the seed space.

---

## 4. Scope

The timestamp reading assumes the generation used `CRandomSeedSetter`'s default rather
than an explicit `SetRandomSeeds(n)` call with a hand-chosen integer. `random.h`
exposes `SetRandomSeeds( int random_seed )` precisely for reproducible runs, and a
puzzle author wanting a fixed alphabet would plausibly use it. **Both readings are
live**; the timestamp one is merely the cheaper to test.

Nothing here bears on FR81's determinacy result. A successful seed sweep would supply
`C` directly, bypassing the redundancy argument entirely — which is the FR89 point that
sweeps and likelihood attacks are independent.
