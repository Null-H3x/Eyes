## 1. Instrumented, and the answer is unambiguous

The generator now records the planted slot→symbol map, so every derived equality
can be checked against ground truth:

```
seed 9000: 117 classes, 117 accepted (106 not fully planted)
   forced equalities 6:  TRUE 0   FALSE 6
seed 9001:  85 classes,  85 accepted ( 56 not fully planted)
   forced equalities 8:  TRUE 0   FALSE 8
seed 9002: 115 classes, 107 accepted ( 92 not fully planted)
   forced equalities 9:  TRUE 0   FALSE 9
```

> **Twenty-three forced equalities across three runs. Every single one is FALSE
> in the alphabet that generated the data.**

**The mechanism:** 90%, 66% and 86% of accepted classes are **not planted
passages** — they are chance isomorphs. Accepting one injects a co-plaintext
constraint that was never true, and enough of them force spurious equalities.

This is FR151's finding (*isomorph does not imply shared passage*) seen from the
generative side, and it is worse than FR151 stated: the false classes do not
merely fail to inform, **they actively manufacture homophones.**

## 2. No threshold rescues it

If accepting only well-attested classes avoided the problem, the model could be
repaired by raising the bar. It does not:

```
seed 9000  surprise>=0.0 : 20 eq (20 FALSE)
           surprise>=3.5 : 20 eq (20 FALSE)
seed 9001  surprise>=0.0 :  1 eq ( 1 FALSE)
           surprise>=3.5 :  1 eq ( 1 FALSE)
```

**Raising the surprise threshold from 0 to 3.5 removes none of them.** The
chance isomorphs that cause the damage are themselves well-attested by the
surprise measure — which is exactly what FR159 found when the `k·log₁₀(83)`
formula overpriced a real alignment by 200×.
